## Definition

An **agent** is anything that perceives its environment and acts upon it. In
the classical formulation, an agent maps its history of percepts to actions, and
a **rational** agent chooses the action expected to do best by some performance
measure. A **language-model agent** is the version now most often meant: a large
language model placed in a loop where it reads the task and everything that has
happened so far, chooses an action — typically calling a tool such as a search
engine, a code interpreter or an API — observes the result, and repeats until it
decides it is done.

## Why it matters

A language model on its own can only produce text from what it already knows.
Given tools, it can look things up, run code, query databases and change the
world — booking, editing files, sending requests. That turns one general model
into something that can complete multi-step tasks, which is what makes agents
worth building. It also changes the risk:
a wrong sentence can be read and discarded, but a wrong action has already
happened.

## Intuition

Picture a capable new colleague with no memory beyond the notebook on their
desk. They read the task, write down what they think they should do, do one
thing, write down what happened, and look at the whole notebook again before the
next step. The notebook is the context window; the colleague is the model; the
things they can do are the tools. The quality of the work depends on the
colleague, the tools and how clearly the notebook is kept.

The analogy flatters the arrangement in one way. A person notices when they are
confused and asks; a model will often continue confidently on a wrong premise,
and each step builds on the last.

## Concrete example

A trace in the style ReAct introduced, interleaving reasoning with actions:

```text
Question:    What is the capital of the country where the Eiffel Tower stands?
Thought:     I need to find where the Eiffel Tower is.
Action:      search["Eiffel Tower"]
Observation: The Eiffel Tower is a wrought-iron lattice tower in Paris, France.
Thought:     It is in France, and the capital of France is Paris.
Action:      finish["Paris"]
```

The loop that produces such a trace is short. Its essential parts are a model
that returns either a tool call or a final answer, a set of tools, a growing
history, and a step budget:

```python
def run_agent(model, tools, task, max_steps=10):
    history = [task]
    for _ in range(max_steps):
        step = model.decide(history)      # a tool call, or a final answer
        if step.kind == "finish":
            return step.answer
        result = tools[step.action](step.argument)
        history.append((step, result))    # the observation feeds the next decision
    raise RuntimeError("step budget exhausted")
```

The budget matters: without it, an agent that never decides it is finished
runs, and spends, indefinitely.

## Formal treatment

In the classical treatment an agent is a function from percept sequences to
actions. When the environment's state is not fully observable, the right action
depends on the whole history, and the agent can be written as a policy

$$
\pi(a_t \mid o_1, a_1, o_2, a_2, \dots, o_t),
$$

choosing action $a_t$ given all previous observations $o$ and actions $a$. A
language-model agent realises this policy by serialising the history as text and
letting the model generate the next action: the policy is the model conditioned
on the transcript. Nothing in the construction optimises the policy for the task
— unlike a reinforcement-learning agent, whose policy is trained on reward — so
its quality rests on what the pretrained model brings to the prompt.

## Assumptions and requirements

- **Actions the model can express.** Tools must be described so that the model
  can choose them and supply arguments in a form the system can parse.
- **Observations that fit.** Everything relevant must fit in the context window,
  or be summarised into it, since the model has no other memory of earlier steps.
- **A way to stop.** The agent needs a termination condition and limits on steps,
  time and cost.
- **Permissions scoped to the risk.** Since actions have effects, what the agent
  may do has to be bounded by what it would be acceptable for it to get wrong.

## Uses and applicability

Agents suit tasks that need several dependent steps and information the model
does not have: research that must search and read, coding that must run and fix,
data questions that must query and compute, workflows spanning several systems.
Standard protocols for exposing tools, such as the Model Context Protocol, let
one agent use tools from many sources. Where a task is a single step, or needs
guaranteed correctness, a plain model call or a conventional program is simpler
and more reliable.

## Limitations and common mistakes

**Errors compound.** A small mistake early in a long task is carried forward, and
per-step reliability that looks high can still make long tasks fail often.

**Tool output is data, not instruction.** Text returned by a tool — a web page, a
document — can contain instructions, and a model that follows them can be steered
by whoever wrote that text. This prompt injection is a security problem, not a
prompt-writing one.

**Loops and early stopping.** Agents repeat actions that did not work, or declare
success without checking.

**Evaluating by demonstration.** A few impressive runs say little; reliability has
to be measured over many tasks, including failures and costs.

## Variants and alternatives

- **Reasoning without acting**, as in chain-of-thought prompting, improves answers
  from the model's own knowledge but cannot fetch anything new.
- **Acting without reasoning** issues tool calls directly; ReAct found that
  interleaving explicit reasoning with actions outperformed acting alone on the
  tasks it tested, though on multi-hop question answering it trailed
  chain-of-thought and did best combined with it.
- **Plan-then-execute** designs produce a whole plan before acting, trading
  adaptivity for predictability.
- **Reinforcement-learning agents** learn a policy from reward; **classical
  planners** search an explicit action model and can guarantee a plan reaches its
  goal under that model.

## History and attribution

The agent is the organising idea of Russell and Norvig's account of artificial
intelligence, framed around rational agents and their environments. The
language-model agent emerged around 2022 as large models became able to follow
instructions and use tools; Yao and colleagues' ReAct paper that year showed that
prompting a model to alternate reasoning traces with actions improved results on
question answering and on interactive tasks, reporting absolute gains in success
rate of 34 and 10 points over imitation and reinforcement-learning baselines on
its two interactive benchmarks.

## Sources

rational-agent framing. The ReAct paper is the source for interleaved reasoning
