## Important decisions

- Host toolchain is unchanged from v1: Node v22.14.0 from `/Users/nick/.nvm/versions/node/v22.14.0/bin`, which every build command puts on `PATH` first because the host default `node` is v26 and the project pins `engines: >=22 <23`.
- J02 content baseline — SHA-256 of each canonical page, frozen so K08 can prove the richer v2 model rewrote nothing: backpropagation-through-convolution ac5e64a3, convolution b2bf2651, convolutional-layer 76156beb, cross-correlation 1429387d, lenet 76c55072, pooling bf2e934d, receptive-field 6c361e06, residual-connection e341c713, resnet e04f7a1c, translation-equivariance 2423c311, vgg 9e27b75a. Full 64-character digests are in the scratchpad file j02-content-hashes.txt and are reproducible with the command above.
- Prettier checks every tracked Markdown file, so V2_BUILD_STATE.md is kept prettier-clean (blank line after each heading, underscore emphasis). The scratchpad helper that maintains it emits that shape directly rather than relying on a later formatting pass.
- V2_BUILD_STATE.md is listed in .prettierignore alongside BUILD_STATE.md rather than kept prettier-clean by hand. The two state files are appended to by a helper on every checkpoint, and a formatter fighting that helper would fail make check for a reason unrelated to the product.
- generated/graph.json is tracked and carries a builtAt timestamp, so any local compile shows it as modified. That churn is expected and is committed at phase boundaries rather than suppressed; the corpus hash beside it is the field that actually means something, and it is unchanged.
- Atlas category paths resolve in two forms. Each category registers its full display path (Artificial Intelligence/Domains/Computer Vision) and, when the title is unique inside its area, the short Area/Title form (Artificial Intelligence/Computer Vision). The eleven v1 pages were written before the atlas existed and use the short form, and freezing Appendix A means Computer Vision genuinely sits under Domains. Registering both keeps the frozen hierarchy and the frozen content true at once, with no change to either. A duplicated title inside one area is rejected outright, so the short form is never ambiguous.
- content/atlas.yaml was generated by a scratchpad script that reads Appendix A out of the runbook rather than retyping it. The script is not tracked; the durable guarantee is packages/core/tests/atlas-seed.test.ts, which re-parses Appendix A in TypeScript and asserts the atlas matches it label for label. Two independent parsers agreeing is stronger evidence than a generator nobody re-runs.
- Claim-level evidence is required for review_state source-checked, expert-reviewed or formally-verified, full stop, rather than only for pages "created or modified after v2". Git history is not available to the validator, and no page has ever been promoted, so the two readings agree today; making it unconditional means the rule cannot be evaded later by editing an old page in place.
- DOTTED_ID was relaxed so that segments after the first may begin with a digit: ^[a-z][a-z0-9_]*(\.[a-z0-9][a-z0-9_]*)+$. The v2 section 4.4 worked example uses source_id paper.resnet.2015, which the v1 regex rejected, and CONCEPT_SLUG already allowed a digit-leading name segment such as /concepts/3-sat that no concept_id could then match. The first segment still must start with a letter, so no id begins with a digit, and no existing id changed. Two new schema tests pin both halves of the rule.
- The corpus hash covers canonical identities only — Markdown pages and graph-only YAML — and the atlas gets its own atlasHash. The corpus hash means "what the corpus says", and v1 documents it that way (README backup/recovery compares it); folding editorial structure into it would make an atlas edit look like a knowledge change. Both hashes are reported by navigator validate and both are compiled into build_meta.
- V1 tests that asserted the literal schema version 1 were updated to assert the SCHEMA_VERSION constant, which L00 requires to be 2. Six assertions across four files changed; each now pins the constant rather than a number, so a future bump cannot silently pass. The index handle still refuses anything newer than the constant, which is what the rule protects.
